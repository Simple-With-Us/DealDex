# 2026-10-29 — Scheduled iOS gate keeps push last-match-wins

Kody review on the push-paths gate flagged the one documented semantic gap: every `!` exclusion compiled to git `:(exclude)`, which always wins, while push re-includes on a later positive match.  A future paths list with an exclusion plus a later re-include would ship on push but skip on the scheduled backstop, reopening the missed-ship gap the gate exists to close.

`scripts/ios-scheduled-ship-gate.sh` now evaluates the ordered `--path-prefix` list with push last-match-wins semantics.  Exclusions with no later positive still compile to `:(exclude)` (no extra git calls, identical behavior); each remaining exclusion becomes a TAB-separated record of the stripped pattern plus its later positives, applied as a set difference after the git match -- a file drops only when it matches the exclusion and none of the later positives.  Both match sites (the reachable-range diff and the timestamp fallback) go through one `matching_files` helper, so the two paths cannot diverge again.  A TAB inside a pattern degrades to a pure exclusion (fail toward skipping).

Tests: `scripts/test-ios-scheduled-ship-gate.sh` gains section 9b (range path: a re-included-only change ships, the same change without the re-include skips) and 11b (timestamp fallback with future-dated commits: excluded-only skips, re-included ships) -- 24 checks, all passing, with the three re-include assertions verified red before the fix.  `node --test` on the gate wrapper plus `ios-ship-workflow.test.mjs` passes 10/10, and the ios-fleet unit and bash suites stay green.  No pin script exists in this repo, so that step was a no-op.
